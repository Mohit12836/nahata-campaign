# Instructions for Codex / Antigravity / AI Research Agents

Before doing any work under `kiosk-intelligence/`:
1. Read `README.md`, `DATA_MODEL.md`, `RESEARCH_SOP.md`, `RETRIEVAL_GUIDE.md`, and `SECURITY_AND_RELEASE.md`.
2. Find the existing `service_id` first. Never create duplicate services per sector, customer audience or region.
3. Distinguish permanent `service_id`, temporary `cycle_id`, versioned `recipe_id`, and evidence `source_id`.
4. Do not invent official fees, form dates, URLs, eligibility, required documents, local demand or margins.
5. No VERIFIED fact without primary official evidence, precise verification timestamp and review.
6. Never commit personal records, Aadhaar numbers, phone numbers, OTPs, real applicant examples, scans, tokens or webhook secrets.
7. Do not automatically rewrite or merge `main`, production extension code or pilot branches based on unapproved research.
8. For every changed public fact, keep old value, new value, reason, evidence and effective date; review before release.
9. Run `python kiosk-intelligence/tools/validate_catalog.py` before any catalog pull request.
10. Answer retrieval questions from structured IDs first, then verified source text; always display last verified date and uncertainty.
11. Consult the current AutoForm feature branch read-only until security issues are remediated; production acceptance is not implied by 97 local mock tests.
12. Report completed work, branch name, commit, test output, outstanding blockers; do not claim the monitoring engine is running unless it actually is.

**When asked to work on 300–500 services:** first maintain `source_registry`; populate verified unique service records in batches; fill `service_versions`, cycles and process/recipe docs only when sourced. The default catalog starts with zero verified rows.
